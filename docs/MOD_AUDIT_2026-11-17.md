# Mod system audit (2026-11-17)

A dated, one-off audit of how well the port handles mods it has **not** been tuned on. It is the evidence base for the
design in [`MOD_COMPAT_DESIGN.md`](MOD_COMPAT_DESIGN.md). It is history and is not kept current: the mod-loading contract
is [`MODS.md`](MODS.md), and status lives on the roadmap (group `modc`).

Method:
- Ran `alamo_mod_check` (MSVC Release build of `claude/vis1-802514`, 2026-11-17 11:10) on base FoC and on every mod
  installed on Gabriel's PC.
- Ran `formats_validate` over every loose `.alo` / `.ala` file of the four reference mods.
- Four read-only reviews (data / XML, Lua / story / AI, assets / UI / packaging, the wider modding ecosystem from public
  sources). Their claims were spot-checked against the code; the checked ones are marked ✔.

Nothing was built or changed. "Not checked" means what it says.

## 1. Summary

The port is already strong where the `modc` group has worked:
- **Loading.** Every installed mod loads with **0 errors**, including two submods stacked on a parent and a three-level
  stack.
- **Lua.** All 466 retail Lua globals and methods are bound. The five mods with Lua call **no engine function the port
  lacks**.
- **Shaders.** They translate, SM3 and `.fx` sources included.
- **Determinism.** The four reference mods pass the headless checklist and are deterministic (`MODS.md` §10.4).

The gaps for an **arbitrary** mod fall into five kinds. None of them shows up in today's load report.

1. **Silent honour gaps.** Many tags retail reads are parsed and stored, but no game code uses them:
   - about 95 gameplay-relevant object-type tags;
   - about 140 GameConstants tags;
   - ability and faction tags;
   - the campaign tag `Special_Case_Production` (936 uses in base FoC alone).

   The load report counts all of these as "read". Separately, 18 retail story reward types are not implemented and are
   skipped with only a log line.
2. **Port limits below retail:**
   - 64 players (one per faction in galactic);
   - AI level normalisation fixed at 5 ✔;
   - AI fleet distance fixed at 100 ✔ (`engine/ai/src/galactic_ai_tokens.cpp:275-276`), although GameConstants defines
     both;
   - `.ted` grids of at most 1985 vertices;
   - 256 Lua `Company_Units` views;
   - 512 fog cells per axis.
3. **Strict parsers where retail is probably lenient.** These cases lose data:
   - one bad count rejects a whole model or animation;
   - one bad count in the text DAT shows every string as its raw key;
   - UTF-16 XML is fatal ✔ (`engine/data/src/xml.cpp:152`), and fatal for the whole load when it is a list file;
   - a second top-level element in an XML file is dropped;
   - outside object types, a boolean only counts as true when written `yes` / `true` / `1` / `on`. Retail also takes any
     value starting with `Y` or `T`.
4. **Recorded but not drawn.** These script calls change no picture:
   - `Hide_Sub_Object` ✔: 806 calls in five mods, and 279 in base FoC itself;
   - the cinematic-layer calls and the hyperspace-in arrival visual.

   Also, the text language is fixed at English.
5. **No asset check.** `alamo_mod_check` does not decode a mod's art, sound or text, so a mod can pass the checklist with
   invisible units. Loose-file sweep result: **73 of about 40,700** model and animation files are rejected by the port's
   parser.

## 4. Data / XML layer

**Already retail-faithful (object types).** Booleans are `1` or a first letter `Y` / `T`. Numbers follow the atoi / atof
prefix rule. Lists split on space, comma, tab and newline. An unknown enum value logs "Failed to convert" and leaves the
field unchanged. `TBD` and empty values are skipped. Scalars are last-wins. Names are case-insensitive (`OBJECT_TYPES.md`
§4.5, §9).

**Honour gaps.** The tag is in retail's table and parsed, but no reader was found outside `engine/objects`. This is a
grep heuristic, so expect noise both ways:

| Class | Rows | No reader | Used in FoC XML | Gameplay-relevant (estimate) |
|---|---:|---:|---:|---:|
| Object type | 892 | 225 | 201 | ~95 |
| GameConstants | 615 | 307 | 291 | ~140 |
| Faction | 302 | 186 | 183 | ~17 |
| Abilities | 354 | 85 | 67 | ~24 |
| Campaign | 51 | 26 | 12 | ~7 |
| HardPoint | 62 | 11 | 8 | — |
| CommandBar | 103 | 21 | — | — |

Examples, by class:
- **Campaign:** `Special_Case_Production` ✔ (no reader, no `docs/re` spec), `Is_Listed`, `Is_Autoresolve_Allowed`,
  `Autoresolve_Exclusion_Locations`, `Corruption_Level_Override`.
- **Object type:**
  - production and limits: `Size_Value`, `Tactical_Production_Queue`, `Required_Timeline`, `Can_Be_Only_One`,
    `Build_Limit_Lifetime_For_All_Allies`;
  - targeting and projectiles: `Turret_Targets_*`, `Fires_Forward`, `Projectile_Max_Scan_Range`,
    `Projectile_Blast_Area_Dropoff(_Tiers)`;
  - tech level: `Tactical_Build_Increments_Tech_Level` / `Tactical_Destruction_Decrements_Tech_Level`;
  - retreat and respawn: `Disallows_Hyperspace_Retreat`, `Respawn_Whole_Team_When_Killed`;
  - Underworld economy: `Cheap_` / `Expensive_Bribe_Cost`, `Cash_Point_*`.
- **Abilities:** `Affects_All_Allied_Sources`, `Interval_Multiplier`, `Damage_Absorb_*`, `Unit_Strength_Category`.
- **GameConstants:** `MaximumStarbaseLevel`, `MaximumGroundbaseLevel`, `Progressive_Taxation`, `Income_Redistribution`,
  `Skirmish_Buy_Credits`, `Max_Remote_Bombs_Per_Player`, `Random_Story_*`.

**Parsing differences from retail:**
- **Booleans.** GameConstants, abilities and planet / campaign flags use `data::parse_bool`, which accepts only
  yes/no, true/false, 1/0 and on/off (`values.cpp:112`).
- **Duplicate tags.** Factions, abilities and campaign `raw_value` are first-wins (`XmlNode::child`), while the object
  view and GameConstants are last-wins. Retail's rule for factions and campaigns is not checked.
- **Integer overflow** gives the default (retail clamps).
- **UTF-16 XML** is fatal ✔.
- **A second top-level element** only warns, and its types are lost.

**Element-tag dependence.** Planets come only from `<Planet>` elements. Galactic role is taken from the element tag
first, and 9 vanilla tags are forced to Other, marked "[port ... open, needs a decision]" (`galactic_rules.cpp:121-170`).
Retail says the element tag carries no behaviour (`OBJECT_TYPES.md` §1).

**Port caps:**

| Cap | Where |
|---|---|
| 64 players; galactic refuses more than 64 factions | `command.hpp:36`, `sim_host.cpp:574` |
| Level maxima 5 ✔ | `galactic_ai_tokens.cpp:276` and four clamps |
| Fleet distance 100 ✔ | `galactic_ai_tokens.cpp:275` |
| Game-spec tech clamped to 1..5 | `game_session.cpp:123` |
| `.ted` grid 1,985 vertices | `ted.hpp:37` |
| Fog 512 cells per axis | `fog_grid.hpp:34` |
| Lua `Company_Units` 256 | `vm_internal.hpp:356` |

Retail-cited limits that stay: 8 battle sides, 3 orbit slots, tech 0..5 spawn slots, the first 2
`Unit_Abilities_Data` entries, and the fixed enums.

**Port rule that changes every mod's balance:** squadron resize to `kPortSquadronSize` with prices scaled (Gabriel,
2026-11-13; `--squadron-size 0` restores retail).

**Fatal at load:** a missing or unparsable `GameConstants.xml`, `GameObjectFiles.xml`, `TradeRouteFiles.xml` or
`CampaignFiles.xml`; zero factions; an unknown skirmish faction or planet; more than 64 players. Retail's handling is not
documented.

## 5. Scripting layer

**Lua API.**
- **Coverage:** 143 globals (135 implemented, 8 host values) and 323 of 323 methods (`logs/lua_binding_coverage.txt`,
  2026-11-12). Mods call 119 distinct globals and 253 methods, all bound. Two calls go to names that exist nowhere: the
  mods' own bugs, which retail fails on too.
- **No-ops where retail acts:** `LandTaskForce.Release_Reinforcements` and `Enable_Attack_Positioning`
  (`bind_ai_tactical.cpp:262,360`). The second has 48 call sites in 5 mods.
- **Recorded but never consumed by `alamo_game`:**
  - `Hide_Sub_Object` ✔: 806 calls in mods, 279 in base;
  - `Cinematic_Hyperspace_In` visuals (310);
  - `Promote_To_Space_Cinematic_Layer` (79);
  - `In_End_Cinematic` (67);
  - `Do_End_Cinematic_Cleanup` (33);
  - `Cancel_Fast_Forward` (26).

**Runtime differences:**
- `require` sets `_LOADED` before the chunk runs ✔ (`lua_vm.cpp:76`; a failed require is never retried).
- AI plan, FreeStore and Evaluator scripts are looked up as `.lua` only.
- Skirmish scoring VMs have no player world (`GAME_SCORING.md:301`).
- `Player_Quit_Event` is never raised.

**Story system.**
- **Events:** 58 of 60 event types are dispatched (the other 2 are dropped by retail too). WIN/LOSE_BATTLES
  composition is empty after auto-resolve.
- **Rewards:** 18 of retail's 139 reward types are unimplemented and skipped with a log line: INFORMATION,
  STATISTIC_CHANGE, PICK_PLANET, SWITCH_SIDES ✔, FLASH_TERRAIN, SET_HEALTH, FLASH_UNIT, DUAL_FLASH, RANDOM_STORY,
  DISABLE_SPECIAL_STRUCTURE, SET_SPAWN, SET_WEATHER, FORCE_RETREAT ✔, ENABLE_OVERWHELMING_ODDS, ENABLE_SABOTAGE,
  RESTRICT_ALL_ABILITIES, RESTRICT_BLACK_MARKET, ENABLE_COMBAT_CINEMATIC. TR uses SWITCH_SIDES (6) and FORCE_RETREAT (2).

**AI.**
- **Equations:** an unknown token fails the whole equation, as retail does. Of the 197 token paths in the mods' perception
  equations, none found unimplemented in heavy use.
- **Tooling:**
  - The token-coverage test targets the old `GalacticTokenResolver`, not the in-game `GalacticSimTokenResolver`.
  - `implements()` is a hand list that misses evaluated paths (e.g. `FRIENDLYFORCE.HASSPACEUNITSBITFIELD`, 301 uses).
  - `alamo_mod_check` has no perception-coverage section.
  - `Game.TIMELINE` returns 0 (`[port: unknown]`).

## 6. Assets, presentation, packaging

- **MEG:**
  - Lookup is a binary search on CRC, and `verify()` is never run at mount, so an unsorted MEG from a mod tool loses
    files silently.
  - Names are not normalised for `/`.
  - Encrypted v3 archives warn and are skipped (no FoC tool writes them).
- **Models and particles:**
  - The ALO / ALA and particle parsers throw on any count mismatch, and the asset is lost (`docs/formats/validation.md`;
    sweep in §3).
  - Unknown chunks are skipped.
  - No bone cap on the native path.
- **Textures:**
  - Supported: DXT1-5, the D3D9 RGB / luminance / alpha formats, DX10 BC1-3, cubemaps, TGA types 2/3/10/11, BMP.
  - Magenta instead: V8U8 / Q8W8V8U8 / CxV8U8, ATI1/ATI2 (BC4/BC5), 16-bit-per-channel and float formats, P8, volume and
    partial cubes, and colour-mapped TGA.
  - A candidate that exists but fails to decode is final: no `.dds` retry.
- **Text and fonts:**
  - The language is fixed at `ENGLISH` (`game_ui.cpp:33`).
  - One bad count in a DAT rejects the whole file.
  - Fonts are loose files only, never from MEGs.
- **Video:** Bink 1 only. Bink 2 reports "not a Bink file".
- **GUI:** the game does not start when a mod's `GUIDialogs.rc` / `.xml` or `MT_CommandBar.mtd` / `.tga` fails to load
  (`game_ui.cpp:15-30`). There is no fallback to the base file.
- **Launcher:**
  - A submod enabled without its parent gets no warning, and the parent is not added. Parent detection exists only in
    the crash bisect (`bisect.rs:455`).
  - Install discovery is Steam only.
  - `modinfo.json` `dependencies` are not used.
- **Fuzzing:**
  - Fuzzed: XML, MEG, ALO, ALA, textures, `.fx`.
  - Not fuzzed: TED, DAT, MTD, `.rc`, anim clips, particle data, `.lc`, the audio and video inputs.
  - Fuzzing is not in ctest or the gate.

Non-Star-Wars total conversions (Stargate, Halo) exist and replace every faction.

**Conventions:**
- `modinfo.json` is the AlamoEngine-Tools `eaw.modinfo` community spec. The game does not read it. Its fields: name,
  version, `languages`, `steamdata`, and ordered `dependencies` with a resolve layout.
- Base-EaW mods run through `sweaw.exe` and do not load under FoC.
- Custom launchers (RaW, Stargate) only build the command line and patch to the newest retail version.
- No DLL-injection mods were found. Large-address (4 GB) patching is obsolete since the 2023 64-bit update.

**Steam-patch features mods rely on.**
- Bound in the port ✔: `Lock_Tech` / `Unlock_Tech`, `Create_Position`, `PositionWrapper.Get_XYZ` (`binding_table.inc`).
- 64-bit category masks: the data review found the type masks are 64-bit.
- Lua object ids in tactical: not checked.
